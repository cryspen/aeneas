**Phase-A inflection point (Session 5 wrap, 2026-05-17)** — surfaced
by C15 (stepCall) and confirmed by inspection of C16 (stepEndAbs):

* `LStep.call` (paper Step.lean:390-395) declares its post-state as
  `(Ω.setLocal dst.local_ (.sym σ)).bumpSymValId σ` — i.e., a single
  dst-write with no abs installation. But the replayer's `stepCall`
  folds the cert's `absSig` into `absRegistry`. The two sides
  diverge as soon as `absSig ≠ #[]`.
* `LStep.endAbs` (paper Step.lean:407-412) takes `Ω.abs abs = some r`
  as premise. Until `LStep.call` actually installs abs, this premise

   over the array, paired with the `regionAbs : Array AbsId` ids.
   Requires either (a) moving `liftAbsShape` / `liftAbsRoleEntry`
   into `Syntax.lean` (paper) so `Step.lean` can use them, or (b)

  not allow `/-! ... -/` between inductive constructors (the parser
  emits "expected 'lemma'" once it closes the inductive). Use
  `-- single-line` comments between constructor groups instead. Hit
  this twice in M10.0f and M10.0h.

* **Inline `-- comments` inside constructor types**: these are
  parsed as whitespace and don't break the parse, but the inductive
  may close at an unexpected place if the doc comment they precede
  isn't formally attached. Caught in M10.0f for `assign`'s
  multi-line body; resolved by removing the inline comments.

* **Doc-comment placement**: `/-- ... -/` immediately preceding a
  declaration attaches to it. If you insert other declarations
  between the doc comment and its intended target (M10.0h inserted
  `JoinEntryStep` + `JoinChain` between `LStep`'s docstring and
  `inductive LStep`), the parser errors. Convert to `/-! ... -/`
  section comments in that case.

* **`Place` field is `local_`**: `AeneasCheck.Raw.Place` calls its
  base local `local_` (trailing underscore to dodge the `local`
  keyword). Code under `LLBCSharpPaper/State.lean` and `Step.lean`
  uses `p.local_` directly.

* **`Event.matchArm` is 4-arity**: `Event.matchArm` takes
  `(scrutinee : SymExpr) (adtId variantId : Nat) (variantName :

* **`Multiset` notation `{x}`**: works at `Multiset
  (Role × LoanId)` for both `RegionAbs.singleton` and the

* **Per-entry join via auxiliary relation**: M10.0h introduces

### Notes from Session 3

* **Per-event lemma signature pattern**: The 4 sorry'd hint-bearing
  lemmas from M10.0k didn't carry `hRep` as an explicit hypothesis
  (they relied on the section's `variable (hRep : ...)`); but section
  variables don't auto-include for tactic-mode proofs that only
  reference them in tactics. Phase C lemmas added in Session 3
  carry `hRep` explicitly. The 4 still-sorry'd ones will need
  the same fix when they get proved (or we can add `include hRep`
  globally).

* **Place projection assumption (M10.2c)**: `stepMove` / `stepCopy`
  use `placeRootLocal` (the root local, ignoring projection); the
  paper-side `LStep.move` / `.copy` premise is `resolvePlace src
  = some v` which dives deep. To bridge, the soundness lemmas take
  three extra hypotheses: `src.projection = #[]`, `dst.projection
  = #[]`, and `∃ v, st.env[src.local_]? = some v`. These are
  Phase-D-dischargeable (cert emission discipline + future
  WellFormed strengthening).

* **`bumpSymValId` redefined as no-op (M10.2f)**: The paper-side
  `LStep.binop` (and several mutBorrow variants, plus call,
  symExpand) conclude with `(... ).bumpSymValId σ` which would
  bump `freshness.nextSymValId`. But `concretise` always sets
  `nextSymValId := 0` (the replayer doesn't track sym-value ids;
  `CertGen_faithful` carries cert-side monotonicity). The original
  `bumpSymValId` broke `concretise st' = Ω'`. Redefined as a no-op
  in `State.lean`. The `symValIdFresh σ` premise reduces to
  `0 ≤ σ` (trivially true). This refinement is load-bearing for
  the still-pending C8-C10, C14, C16, and C19.

* **`concretise_addLoan` is the next blocker** (M10.2g/C7 onwards):
  Every event that adds a loan (stepSharedBorrow / stepMutBorrow
  family / etc.) needs this commute lemma to discharge
  `concretise st' = Ω'`. The underlying sub-lemma is
  `maxKeyPlusOne (m.insert k v) = max (maxKeyPlusOne m) (k+1)`
  for `Std.HashMap`. Under the freshness premise
  (`maxKeyPlusOne m ≤ k`), the RHS simplifies to `k+1`, so the
  needed sub-lemma is `maxKeyPlusOne_insert_fresh`:
  ```
  maxKeyPlusOne (m.insert k v) = k + 1
    when maxKeyPlusOne m ≤ k
  ```
  Proof skeleton: `Std.HashMap.fold_eq_foldl_toList` →
  `Std.HashMap.toList_insert_perm` → `List.Perm.foldl_eq` with
  `RightCommutative max` instance → simp the result foldl over
  the unfiltered `(k,v) :: m.toList` (the freshness premise makes
  `filter (¬k == ·.1) m.toList = m.toList`). All Mathlib pieces
  exist; the proof is ~30-50 LOC. **Next session: dispatch
  `lean4:sorry-filler-deep` for this lemma in a worktree** while
  continuing other planning.

* **C7 specifically (stepSharedBorrow)**: Once `concretise_addLoan`
  closes, the proof should be straightforward — `stepSharedBorrow`
  on success returns `st.addLoan loan inner .shared` (no env
  mutation); `LStep.sharedBorrow` conclusion is
  `(Ω.bumpLoanId ℓ).bumpSymValId σ` which under the no-op
  `bumpSymValId` = `Ω.bumpLoanId ℓ` — exactly what
  `concretise_addLoan` gives us.

### Notes from Session 4

* **`if_pos` / `if_neg` over `simp only [hC, if_true/false]`**: The
  prior pattern (used in M10.2f stepBinop) of `simp only [hC,
  ite_true]` doesn't reduce `if (false = true) then ... else ...`
  because `if_false` is keyed on `if False then a else b`, not on
  the propositional `false = true`. Using `rw [if_pos hC]` /
  `rw [if_neg hC]` directly handles both the Bool-style guard
  (`st.loans.contains loan = true`) and the Prop-style guard
  (`place.local_ ≥ st.numLocals`). Cleaner and uniform across
  guards.

* **Defining `hFreshSet` for setLocal-then-addLoan**: In C8/C10
  the proof reaches `concretise ((st.setLocal _ _).addLoan loan
  _ _)`. To apply `concretise_addLoan`, the freshness premise must
  match the *intermediate* `(st.setLocal _ _).loans`. Since
  setLocal only mutates `env`, `(st.setLocal _ _).loans = st.loans`
  by `rfl`, but Lean's elaborator won't always unify with the
  underscore-filled lemma instance. Workaround: introduce
  `have hFreshSet : maxKeyPlusOne (st.setLocal _ _).loans ≤ loan
  := hLoanFresh` (the coercion is definitional), then pass
  `hFreshSet` to `concretise_addLoan`. Adds ~3 LOC per such
  lemma; worth it for clarity.

* **`concretise_takeLoan` is potentially unsound as stated**:
  The lemma claims `concretise st' = concretise st` after
  `takeLoan b = some (_, st')`. But `takeLoan` calls
  `loans.erase b`, and `maxKeyPlusOne (loans.erase b) ≤
  maxKeyPlusOne loans` (can strictly decrease if `b` was the
  max key). So `(concretise st').freshness.nextLoanId` can
  strictly *decrease*, violating the literal equality. Phase
  C's first endBorrow lemma (C11) will surface this. Likely
  fix: redefine `concretise`'s `nextLoanId` to be an *upper
  bound* counter that never shrinks (e.g., carry an explicit
  high-water mark in `SymState`, or use `max (maxKeyPlusOne
  st.loans) (cert-supplied bound)`). Defer the design choice
  to when C11 needs it — may also need a `WellFormedProgram`
  strengthening + cert-side monotonicity premise.

* **Worktree auto-merge**: The `lean4:sorry-filler-deep` agent
  with `isolation: "worktree"` was supposed to commit on a
  separate branch (`worktree-agent-<id>`); the orchestrator was
  to fast-forward merge. In practice, the harness *auto-merged*
  the worktree's clean commit into `aeneas-lean-certificate`
  directly (worktree removed; tip moved to `9be15ea7`). No

### Notes from Session 5

* **loanIdHwm redesign**: the Session 4 caveat ("`concretise_takeLoan`
  is potentially unsound as stated") forced a SymState shape change.
  `SymState` gains a monotone `loanIdHwm : Nat := 0` field bumped by
  `addLoan` and never touched by `takeLoan` / `loans.erase`. The
  replayer's checker logic never reads this field — it exists solely
  for soundness. `concretise.freshness.nextLoanId` retargets at
  `st.loanIdHwm` (was `maxKeyPlusOne st.loans`). Two consequences:
  `concretise_takeLoan` closes (no field changes either side);
  `concretise_addLoan` becomes *unconditional* (the LHS `loanIdHwm
  := max old (b+1)` matches the RHS `bumpLoanId b := max old (b+1)`
  by `rfl`). The freshness premise on C7-C10 lemmas renames from
  `maxKeyPlusOne st.loans ≤ loan` to `st.loanIdHwm ≤ loan`; uses of
  `concretise_addLoan _ _ _ _ hFresh` drop the explicit witness.
  Sym-arg `absIdHwm` not yet needed (no event in the current LStep
  surface erases from absRegistry; if endAbs lemma ever does, same
  fix applies).

* **End-borrow trio (C11-C13) contract**: rather than unroll the
  replayer's `for ... in st.env.toList` env-scan loop, each lemma
  takes a Phase-D-dischargeable *result-shape* hypothesis pinning
  st' directly:
  - C11 (.direct / .lazyExpand): `(x, v, stTake, hShape : stepEvent
    ... = .ok (stTake.setLocal x v))` + `hHolder : Ω.ctx x =
    some (.mutLoan loan)`.
  - C12 (.reborrow): `(stTake, hShape : stepEvent ... = .ok stTake)`.
  - C13 (.shared): same as C12.
  Phase D discharges `hShape` and `hHolder` from the `LoanTokenInvariant`
  uniqueness fact (plan §3.4 strengthening). This is the same
  "Phase-D-dischargeable" pattern used by C2-C10 for place-projection
  and env-existence hypotheses.

* **`LocalId` not in scope** at `Soundness/StepEventSound.lean`:
  `LocalId := Nat` lives in `LLBCSharpPaper`, but the file's
  `open AeneasSoundness.LLBCSharpPaper (LLBCState LStep Valid)` is
  selective — `LocalId` is not opened. Lean auto-binds the
  identifier as a polymorphic type variable (`Sort u_1`), which
  triggers a confusing "of sort Sort u_1 but is expected to have type
  ... of sort Type" error. Workaround: use `Nat` directly in
  parameter signatures (matches the pattern of `place.local_ : Nat`
  in the mutBorrow lemmas). If future lemmas need many `LocalId`
  / `AbsId` parameters, broaden the `open` line.
