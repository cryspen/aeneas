### Notes from Session 1

* **CI lane**: M10.0a scaffolds the Lake package only; adding a
  soundness CI job to `.github/workflows/ci.yml` is deferred. The
  existing ci.yml uses the nix flake which doesn't reference the
  checker by name either; the local 7-gate invocation from the
  execution prompt §0 is sufficient until a phase boundary.

* **`aeneas-lean-checker` mathlib-free**: confirmed — its lakefile
  has no `require` lines and the `RuntimeShim` library provides the
  `Aeneas.Std.*` surface that `GeneratedTests` needs without
  pulling in Mathlib. The soundness package's `require mathlib`
  doesn't leak.

* **`StepEventSound.lean` referenced nowhere**: confirmed by grep;
  no re-export shim needed in the checker. Plan §0.1 suggested one
  for safety; not required given the file was orphaned in the
  checker tree.

* **Namespace `AeneasSoundness.Soundness`**: M10.0a retargets the
  namespace from `AeneasCheck.Theorems` so the
  `AeneasSoundness.Soundness.stepEvent_sound` G5 golden line
  resolves without an alias hop.

* **`Place` not `«Place#»`**: M10.0b initially defined
  `abbrev «Place#» := Place` for paper-flavor naming, but the
  French-quote-escaped identifier (`«Place#»`) is unwieldy at every
  use site (Lean's parser doesn't accept `Place#` bare). Dropped
  the alias in M10.0f; downstream files just `open AeneasCheck.Raw
  (Place ProjElem)` and write `Place` / `ProjElem` directly.

* **Section comments inside inductive bodies**: Lean's grammar does
  not allow `/-! ... -/` between inductive constructors (the parser
  emits "expected 'lemma'" once it closes the inductive). Use
  `-- single-line` comments between constructor groups instead. Hit
  this twice in M10.0f and M10.0h.

* **Inline `-- comments` inside constructor types**: these are
  parsed as whitespace and don't break the parse, but the inductive
  may close at an unexpected place if the doc comment they precede
  isn't formally attached. Caught in M10.0f for `assign`'s
  multi-line body; resolved by removing the inline comments.

* **Doc-comment placement**: `/-- ... -/` immediately preceding a
  declaration attaches to it. If you insert other declarations
  between the doc comment and its intended target (M10.0h inserted
  `JoinEntryStep` + `JoinChain` between `LStep`'s docstring and
  `inductive LStep`), the parser errors. Convert to `/-! ... -/`
  section comments in that case.

* **`Place` field is `local_`**: `AeneasCheck.Raw.Place` calls its
  base local `local_` (trailing underscore to dodge the `local`
  keyword). Code under `LLBCSharpPaper/State.lean` and `Step.lean`
  uses `p.local_` directly.

* **`Event.matchArm` is 4-arity**: `Event.matchArm` takes
  `(scrutinee : SymExpr) (adtId variantId : Nat) (variantName :
  String)`. The plan's narrative treated it as `(adtId variantId)`
  only; the M10.0f draft had to be corrected.

* **`Multiset` notation `{x}`**: works at `Multiset
  (Role × LoanId)` for both `RegionAbs.singleton` and the
  `mutBorrows` constructor's role list; no special imports needed
  beyond `Mathlib.Data.Multiset.Basic`.

* **Per-entry join via auxiliary relation**: M10.0h introduces
  `JoinEntryStep` (6 constructors mirroring `JoinRule`) plus
  `JoinChain` (sequential composition over a list of `JoinEntry`).
  `LStep.join` then folds via `JoinChain Ω witnesses.toList Ω'`.
  Cleaner than 6 LStep variants that match `Event.join` with
  specific witness shapes.

* **Premise strength baseline**: every LStep constructor uses
  *baseline* premises that are expressible from Phase A's surface
  (place resolution, freshness counters, top-level
  `directLoanId` / `directBorrowId`). Deep-Val side conditions
  ("⊥/loan^{s,m} ∉ v"), parent-loan liveness, deref-chain
  consistency are deferred to Phase C; if a per-event lemma needs
  one, the Phase-C commit adds the corresponding `WellFormed`
  field. Per plan §3.4.
