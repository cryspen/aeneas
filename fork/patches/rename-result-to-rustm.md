# rename-result-to-rustm

## Summary

Renames the Lean error monad `Aeneas.Std.Result` to `Aeneas.Std.RustM`
(fork PR #37), so that it no longer clashes with the translation of Rust's
`core::result::Result`.

The patch has two commits:

1. the output of `fork/scripts/rename-result-to-rustm.py`, which rewrites
   `backends/lean`, `tests/lean`, `documentation` and the places in `src/` that
   hard-code the monad's Lean name (including re-wrapping the OCaml lines it
   shortens);
2. the re-extracted `tests/lean` outputs: `RustM` is shorter than `Result`, so
   the pretty-printer wraps some lines differently. On 2026-10-07 this commit
   only contained such re-wraps; `make format` and the generated
   `src/extract/*Lean*.ml` had nothing to change.

## Invariants

- No Lean definition of the monad, its constructors' wrappers or its
  instances is named `Result` in `backends/lean`; `core.result.Result`
  (Rust's type), `Simp.Result` and unrelated identifiers are untouched.
- The extracted code refers to the monad as `RustM`.
- `MatchResult` (the result of matching on the monad) is not renamed.

## Tests

- The whole of `tests/lean`; `fork/scripts/rename-result-to-rustm.py --self-test`
  and `--audit`.

## Rebase notes

- Regenerate the first commit by running the script on the new base; never
  resolve its conflicts. Re-run it after every merge: files the base branch
  added still say `Result`.
- The second commit is regenerated by re-extracting the tests (`make test`),
  then `make format` and `make extract-lean-std extract-lean-keywords`. Any hand
  fixups needed on top go into this commit.
