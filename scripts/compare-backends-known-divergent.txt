# G_byte gate: fixtures whose L₀ (mainline) and L₁ (aeneas-check)
# outputs differ in ways that are *known* and *harmless*. One line
# per fixture: <fixture>: <one-sentence reason>. Lines starting
# with '#' are comments. Blank lines are ignored.
#
# Regenerate via `scripts/compare-backends.sh --regen-divergent`,
# then hand-edit each PLACEHOLDER to describe the divergence (or
# fix it). When a divergence is fixed, remove the line.
#
# Session 6 baseline (2026-05-18): 85 of 89 fixtures diverge; 1
# fixture (`blanket_impl`) is byte-identical; 3 fixtures (`closures`,
# `issue-804-closure-return-ref`, `raw_pointers`) skip because
# mainline can't emit them. The 85 divergences collectively fall
# into roughly the following categories (each fixture exhibits one
# or more):
#
#   * Visibility lines — mainline emits `Visibility: public` after
#     each /-- … -/ docstring; aeneas-check omits this.
#   * Param naming — mainline preserves the source's parameter
#     names (`x`, `y`); aeneas-check synthesises `x1`, `x2`, …
#   * Parenthesisation — mainline emits `x + 1#u32`; aeneas-check
#     emits `(x + 1#u32)` (wraps binops).
#   * Source path — mainline records absolute paths in `/-- Source
#     … -/`; aeneas-check records relative paths (depending on the
#     LLBC's build environment).
#   * Decl ordering — different topo-sort produces interleaved
#     `def` / `structure` declarations.
#   * Loop-body factorisation — mainline emits a separate
#     `<fn>::loop body 0` def; aeneas-check inlines.
#   * Missing impl methods / extra impl methods — aeneas-check
#     emits some structures / traits that mainline omits (or vice
#     versa) depending on dead-code elimination.
#
# Future sessions: split categorical reasons per fixture as
# emit-side fixes land; entries should be removed once the
# divergence is resolved.
